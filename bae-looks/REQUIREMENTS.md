# bae-looks 要件定義 v0.2

## 1. プロダクト概要

| 項目 | 内容 |
|------|------|
| プロジェクト名 | `bae-looks` |
| プロダクト名（UI） | **BAE FRAME** |
| 一言 | NMIXX ベイ特化の「動画フレーム → 着用アイテム特定」フロント試作 |
| フェーズ | **v0.1 フロント検証**（モックデータ）。実AI・実ECは未接続 |
| 拡張方針 | フロントの感触が良いと判断できたら、同じUI骨格でメンバー横断・他アーティストへ拡張する |

### 背景課題

推し活で動画（YouTube / TikTok / 配信）やSNSの着用アイテムが気になったとき、

1. 一時停止 → スクショ → Googleレンズ等で検索  
2. 角度・動き・解像度で特定失敗  

という工程が煩雑で離脱が多い。

### 目指す体験（最終形）

動画の任意秒から、推しの着用・愛用アイテムを特定し、確証度つきで購入導線・プチプラ代替まで提示する。  
**いまはベイ一人・フロントのみで「その体験の空気感」を検証する。**

## 2. ユーザーと成功条件

| 項目 | 内容 |
|------|------|
| プライマリユーザー | NMIXX ベイのファン / 推し活ユーザー |
| 解決すること | スクショ検索の代わりに「フレームを選ぶだけで特定が始まる」体験を体感できること |
| v0.1 の成功定義 | 第一印象が良く、「このUI骨格で拡張したい」と判断できること |
| 非ゴール（v0.1） | 実商品の完全一致保証、収益化、本番アフィリエイト |

## 3. MVP機能（v0.1・実装済み）

- [x] ベイ特化ランディング（ブランドヒーローを第一ビューの主役に）
- [x] サンプルモーメント3種の選択（舞台袖 / 空港 / VLOG）
- [x] 特定デモ（約1.6秒のスキャン演出 → 候補カード表示）
- [x] 確証度バッジ（完全一致 / 同一ブランド / 類似）
- [x] 購入導線プレースホルダ（公式 / モール / 類似検索リンク）
- [x] プチプラ・概念コーデの代替提案
- [x] 「なぜベイ一人からか」のスコープ説明セクション

### サンプルモーメント（モック）

| ID | シーン | 注目カテゴリ | 主な確証度例 |
|----|--------|--------------|--------------|
| `stage-silver` | ミュージックショー舞台袖 | ピアス | `similar` / `same_brand` |
| `airport-denim` | 空港ファッション | アウター | `similar` / `exact`（シューズ） |
| `vlog-lip` | VLOG メイクアップ | リップ | `same_brand` / `similar` |

※ 商品名・型番はUX検証用のデモ推測であり、実購入の断定ではない。定義の正は `src/data/moments.ts`。

## 4. 非機能要件

| 項目 | 要件 | 状態 |
|------|------|------|
| レスポンシブ | モバイル / デスクトップで第一ビューとデモが破綻しない | 対応済み |
| モーション | rise / scan / card stagger 程度（2〜3種） | 対応済み |
| 肖像・商標 | 実写肖像を使わず抽象フレーム＋テキスト | 対応済み |
| 認証 | 不要 | — |
| 課金API | 不要（v0.1） | — |
| 品質ゲート | `npm run lint` / `npm run build` が通ること | 必須 |

## 5. スコープ外（v0.1）

- 実動画の取り込み（yt-dlp / 公式API）・フレーム抽出
- 物体検出・セグメンテーション・Vision LLM 本番接続
- 実EC在庫API・アフィリエイト本番契約
- ブラウザ拡張 / ライブ連携
- ベイ以外のメンバー・他アーティストの同時展開
- ユーザーアカウント、お気に入り、投稿コミュニティ

## 6. 拡張ロードマップ（フロント感触OK後）

| 段階 | 内容 | ゲート |
|------|------|--------|
| v0.1 | ベイ特化フロント＋モック（**現行**） | UI承認 |
| v0.2 | ベイ限定で実フレーム解析（1カテゴリから） | 特定精度の目安合意 |
| v0.3 | EC横断検索・確証度の根拠表示の強化 | 誤判定時のUX合意 |
| v1.0 | 同グループ他メンバー or 他アーティストへ入力差し替え | 拡張対象の決定 |

### 未決事項

- 拡張時の最初の追加対象（同グループ他メンバー vs 他アーティスト）
- 収益化（アフィリエイト / サブスク）の優先度
- ファン集合知（特定ログ）をデータソースに含めるか

## 7. 競合ギャップ（設計上の位置づけ）

| 系統 | 例 | 限界 | BAE FRAME の差し込み |
|------|-----|------|----------------------|
| 汎用画像検索 | Google Lens, ZOZO画像検索 | 推しコンテキストなし。スクショ工程が残る | 出演者固定＋フレーム選択で工程を短縮 |
| 有名人衣装DB | コレカウ | 任意のYouTube/TikTok秒には弱い | 任意秒の特定体験をUIから先に検証 |
| クリエイタータグ | LTK, YouTube Shopping, TikTok Shop | 未タグ私服は対象外 | 未タグ前提の「推測＋確証度」UX |

詳細なエージェント入出力は [BASIC_DESIGN.md](./BASIC_DESIGN.md) を正とする。
