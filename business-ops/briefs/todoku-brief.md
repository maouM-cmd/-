# とどく — プロジェクトブリーフ

| 項目 | 記入 |
|------|------|
| プロジェクト名（slug） | todoku |
| タイプ | nextjs |
| 一言説明 | 世帯状況を聞くと、東京都の支援制度が順位付きで届くマッチングアプリ |

## 目的・ユーザー

- **誰のため:** 制度があるのに自分向けか分からず申請していない都民（ひとり親・子育て世帯・介護世帯）
- **何を解決する:** 支援制度の取りこぼし（探すコスト＝手取り時間の減少）
- **成功の定義:** 3ペルソナでランキングが変わり、適合理由・手続・推定時短が2分デモで伝わる

## MVP機能（3つまで）

1. ペルソナ3種（ワンクリック）＋世帯3問フォーム
2. 制度カード一覧（適合度％、理由、手続、推定時短・手取り目安）
3. 静的JSONの制度マスタ（約20件、オープンデータ項目に寄せたデモデータ）

## 技術選定

| 項目 | 選択 |
|------|------|
| フレームワーク | Next.js 16 + TypeScript + Tailwind CSS 4 |
| DB | なし（静的JSON） |
| ホスティング | Cloudflare Pages 想定（`output: "export"`） |
| 参考プロジェクト | optimal-match（スコア） / ai-dashboard-kit（静的JSON） |

## 公式テーマ（テーマあり）

- 主: 生活「家庭の状況や困りごとに応じた、手当・助成などの支援制度や福祉サービスの案内」
- 副: デジタル「個人や世帯の状況に応じて、手続や支援制度などの情報が自動的に届く仕組み」

## スコープ外

- 生成AIによる適格の最終判定（コアはルール＋スコア）
- 地図・防災・熱中症ルート
- ログイン・個人情報の保存
- カタログ外データのスクレイプ
- 既存 `optimal-match` の改変

## 制約・注意

- 課金が発生するサービス: なし（ローカル／静的ホスト）
- 認証が必要: いいえ
- 判定はデモ用の簡易ルール。申請可否は各窓口の正式判定に従う
