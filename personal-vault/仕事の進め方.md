# 仕事の進め方

> ツール、自動化、エージェント委任の境界。`AI_AGENT_MASTERY` と整合させる。

## 事実

### 集中できるとき

- **目的やゴールが明確**なとき
- **何をすればいいか・どう進めればいいか**がわかりやすいとき → 集中できる

### 疲れるとき

- **エラーが解消できない**とき
- **上司やお客様との会談**があるとき
- **自分に責任がある仕事**があるとき

### 主業務・くり返し作業（BUSINESS_MAP より）

- **主業務:** Web開発
- **くり返し作業:** GitHub投稿（commit / push / PR）
- **最大ボトルネック:** 新しい成果物のゼロからの立ち上げ
- **よく作る成果物:** 開発成果物（アプリ、設計書、PR）
- **主要ツール:** GitHub, Cursor, Dify, Docker, AWS

### 副次業務（リポジトリから推定）

- 副業記事（`articles/`）
- 運用中アプリ（`coupon-board/`）
- 開発キット（`ai-dashboard-kit/`）

### エージェント委任の境界（AI_AGENT_MASTERY より）

| 任せる | 人間がやる |
|--------|-----------|
| 調査、コード、テスト、文案、設計書ドラフト | push、merge、デプロイ、課金、外部投稿、秘密情報 |

### エージェント活用の最終像（対話より — 詳細は [[目標とビジョン]]）

- エージェントが**自立的に一通りの工程を完遂**する
- 指示する人間も、**AIが何をしたか理解できているか**をちゃんと確認できる状態にする

## 解釈

- **明確さが集中の前提** — ゴール・手順が見えていると没入しやすい（[[成り立ち]] の「集中していないとメンタルが持たない」とも接続）
- **不明瞭・責任・対人**が疲労のトリガー — エラー停滞、会談、責任ある仕事はいずれも「不確実性」や「他者評価」が絡む
- エージェント活用の目的は単なる自動化ではなく、**工程の完遂**と**人間側の理解の担保**の両立
- 上司・お客との会談が疲れる点は、[[考え方]] の「取り繕い・対人疲れ」とも重なる可能性

## 具体例

### 施策レコメンド案件のワークフロー

1. 中間マニュアルを作成
2. Dify で回答を生成
3. RAGAS で検証

### 集中 vs 疲労の対比

| 集中できる | 疲れる |
|-----------|--------|
| ゴール明確 | エラーが解消できない |
| 次の一手がわかる | 上司・お客との会談 |
| | 自分に責任がある仕事 |
