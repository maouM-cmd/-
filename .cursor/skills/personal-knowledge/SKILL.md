# パーソナルナレッジ対話 Skill

## ゴール

> 対話で引き出した「自分のこと」を `personal-vault/` に構造化し、ユーザーがローカル Obsidian に取り込める状態にする。

## 起動

- `@personal-knowledge`
- 「自分のことを話したい」「成り立ちを話したい」等の依頼

## セッション前（必須）

1. `personal-vault/00-MOC-プロフィール.md` を読む
2. 対象テーマのノート（例: `成り立ち.md`）を読む
3. `personal-vault/sessions/` の直近ログを読み、続きか新規か判断する

## 対話ルール

| ルール | 内容 |
|--------|------|
| 質問数 | **1セッション 2〜4 問**に絞る |
| 形式 | 箇条書きで答えやすい質問。長文を求めない |
| 深掘り | 抽象的な回答には具体例を1つだけ追加で聞く |
| 推測 | 回答がない部分は推測で書かない。「未記入」のまま残す |
| 確認 | セッション末尾に「今回追加した内容」サマリを提示 |

## テーマ順序（複数セッション可）

1. **成り立ち** — 幼少期〜現在の転機、きっかけ、影響を受けた人・出来事
2. **価値観** — 譲れないこと、嫌なこと、尊敬する姿
3. **考え方** — 意思決定の癖、迷ったときの判断基準、失敗から学んだこと
4. **仕事の進め方** — ツール、自動化、エージェント委任の境界
5. **目標とビジョン** — 短期・長期、「最強AIエージェントマスター」の具体像

**続きの検出:** 対象ノートの `status: draft` かつ「（対話で追記予定）」が残っていれば、前回の `sessions/` ログの「次回の問い」から再開する。

## 書き込みルール

### 更新先

| 種別 | パス |
|------|------|
| 本ノート | `personal-vault/{テーマ}.md` |
| 対話ログ | `personal-vault/sessions/YYYY-MM-DD-{テーマ}.md` |
| 目次 | `personal-vault/00-MOC-プロフィール.md` の状態・ログリンクを更新 |

### ノート構造（本ノート）

```markdown
## 事実
（客観的に言えること、経歴、出来事）

## 解釈
（本人の意味づけ、学び、価値観への接続）

## 具体例
（エピソード、場面、固有名詞は shareable に注意）

## 関連
（wikilink: [[価値観]] 等）
```

### frontmatter（必須キー）

```yaml
title: ...
tags: [...]
created: YYYY-MM-DD
updated: YYYY-MM-DD   # 更新のたびに今日の日付
status: draft | stable
shareable: true | false  # 記事・コードに流用してよいか
```

### 対話ログ構造

`templates/session-log-template.md` に従う:

- 質問（エージェントが投げた問い）
- 回答（生）— ユーザーの言葉をできるだけそのまま
- 蒸留メモ — 本ノートへ反映した要点
- 次回の問い — 次セッション用

### 業務情報の扱い

- `business-ops/BUSINESS_MAP.md` / `AI_AGENT_MASTERY.md` の内容は **複製しない**
- `仕事の進め方.md` / `目標とビジョン.md` には要約 + ファイルパス参照で十分
- 対話で新しい個人的な文脈が出たら、業務ドキュメントとの差分を本ノートに書く

## セッションフロー

```
1. 既存ノート・ログを読む
2. テーマを宣言（例: 「今日は成り立ちの続きです」）
3. 2〜4 問を投げる
4. ユーザー回答を受け取る
5. sessions/ にログを書く
6. 本ノートを更新（事実 / 解釈 / 具体例）
7. MOC の状態を更新
8. サマリを提示 → 誤りがあれば修正
9. git commit（personal-vault 変更時）
```

## 初回質問バンク（成り立ち）

1. 今の仕事（Web開発）に至った流れを、時系列で3〜5つの節に分けるとしたら何ですか？
2. その中で「人生の分岐点」になった出来事はどれですか？当時どう感じましたか？
3. 今の自分を形づくった人物・環境・体験を、思いつく限り挙げてください。

## 安全・プライバシー

- `shareable: false` の内容を記事・公開コードに流用しない
- 固有名詞（会社名、人名）はユーザーが明示的に OK するまで匿名化（例: 「前職の会社」）
- セッションログは原則 `shareable: false`

## QA

セッション後、変更があれば:

```bash
node business-ops/scripts/knowledge-vault-qa.mjs
```
